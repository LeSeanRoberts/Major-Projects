Portfolio Risk & Performance Analytics for a Public Pension Fund Using NYC Comptroller BERS Holdings Data

Abstract

All portfolio analytics were conducted using the most recent fiscal year snapshot (Period End date) to ensure values represent the current holdings and avoid double counting across historical periods. Project serves to exhibit highly basic portfolio analysis via data wrangling for public investment funds, particularly for New York City governance.

Introduction

Public pension funds manage billions of dollars on behalf of retirees and taxpayers, requiring careful oversight of investment allocation, risk exposure, and financial performance. Effective portfolio analytics help ensure diversification, control downside risk, and maintain long-term solvency.

This project analyses security-level holdings data from the Board of Education Retirement System (BERS), provided through NYC Open Data by the Comptroller’s Office. This data was first made public on October 29th, 2018; last updated on March 3rd, 2025. The dataset contains detailed information on fixed income and other investments, including market values, costs, unrealized gains and losses, credit ratings, maturities, and industry classifications.

Using R, this study develops a suite of practical portfolio analytics that mirror workflows used in asset management, pension oversight, and financial risk management. The analysis focuses on (some of) the following:

  • Asset allocation

  • Diversification and concentration risk

  • Investment performance

  • Credit quality exposure

  • Interest rate (duration) risk

  • Predictive modeling of losses

Together, these components provide a comprehensive picture of the fund’s financial health and risk profile.

The last function above (max_date), this finds one single date only:

\[ \text{max date} = \max_{i}(\text{period end date}_{i}) \]

So this is just the latest reporting date in the entire dataset.

Mathematically this is:

\[ df_{latest}=\{i:\,\text{period end date}_i=\text{max date}\} \]

Of consequence, only rows from one date is kept, and discarding all others.

Goal: determining where (how) money is invested.

Calculating the proportional distribution of market value across different asset classes. Since the data treats each asset entry as an independent observation, the mathematical structure follows a standard aggregation and normalization pattern.

Data Grouping and Summation:

Partitioning the data into subsets based on the category \(j\), representing each unique asset class in the asset_class attribute. For each class, it calculates the total market value \(V_j\) by summing the individual market values \(v_i\) of all assets belonging to that class.

\[ V_j = \sum_{i \in \text{Class}_j} v_i \]

where:

\(V_j\) : The aggregate market value for asset class \(j\).

\(v_i\) : The base_market_value of an individual observation \(i\)

Global Total Calculation:

To determine the weights, there’s implicit calculation of the total market value \(V_{total}\) across all asset classes combined:

\[ V_{\text{total}} = \sum_{j=1}^{n} V_j \]

Weight Derivation (Normalisation):

Finally, there’s step of “mutation” which applies a normalisation to acquire the relative weight \(w_j\) for each asset class. This ensures that the sum of all weights equals 1 (or 100%).

\[ w_j\,=\,\frac{V_j}{V_{total}} \]

alloc <- portfolio_df |>

Tax-Efficient Rebalance:

Moving from aggregate math to individual lot selection. Since each row in the dataframe represents a unique, independent purchase, to then rank them based on their “tax cost.”

The Strategy: HIFO vs. LOFO

  • HIFO (Highest In, First Out): Selling the shares you bought at the highest price. This minimizes the realized gain.

  • LOFO (Lowest Out, First Out): Selling lots currently at a loss (Tax-Loss Harvesting) to offset gains elsewhere.

The Mathematical Ranking

For each (independent) instrument for asset class considered, to calculate unrealised gain/loss ratio:

\[ G_i\,=\,\frac{P_{current}\,-\,P_{purchase,\,i}}{P_{purchase,\,i}} \]

To minimize tax, sorting the data in manner to sell rows where \(G_i\) is identified as the lowest (or most negative) first.

Caveat Concerning original_face

In many financial datasets, Face Value is a common substitute for cost, but it carries a specific mathematical distinction to be aware of before implementing any rebalancing.

While original_face represents the par value, the amount the issuer or equity (promises) to pay back (at maturity or “punch in sell”), it’s not always what you actually paid (purchase cost or something similar).

  • If bought at Par: \(Original\,\,Face=Purchase\,\,Cost\)

  • If bought at a Discount: \(Original\,\,Face\,>\,Purchase\,\,Cost\) (e.g., Zero-coupon bonds)

  • If bought at a Premium: \(Original\,\,Face\,<\,Purchase\,\,Cost\)

For Equity, “Original Face” is less common; customarily observed is “Book Cost” or “Cost Basis.” However, for Fixed Income, using Original Face as a proxy for cost will give provide an approximation of the “Principal” invested, rather than the “Market Value.”

Concerning inflation-linked or amortizing assets, since the data treats each instrument as independent, one must also check if any of theassets are amortizing (like Mortgages) or inflation-linked (like TIPS).

Use of Local Total Cost Amount for Tax-Rebalancing

Local Total Cost Amount represents the actual Cost Basis. In tax accounting, your realised gain/loss is calculated as:

\[ \text{Realised Gain/Loss}\,=\,\text{Market Value}\,-\,\text{Cost Basis} \]

Using this atrribute or column ensures correctly identifying “lots” with the highest cost relative to their current value, permitting Tax-Loss Harvesting.

To identify the best rows to sell to reach the ~70% Equity target, the rationale should appear like the following:

\[ G_i\,=\,\frac{V_i-C_i}{C_i} \]

where

\(V_i\) = base_market_value

\(C_i\) = local_total_cost_amount

rebalance_candidates <- portfolio_df |>
  # Filter out Cash (usually has 0 gain/loss)
  filter(asset_class %in% c("EQUITY", "FIXED INCOME")) |>
  mutate(
    # Calculate the dollar gain/loss per independent trip
    unrealised_gain_loss = base_market_value - local_total_cost_amount) |>
  mutate(
    # Calculate percentage for better comparison across different trip sizes
    gain_pct = (unrealised_gain_loss / local_total_cost_amount) * 100) |>
  # Sort so that the best "Sells" (the biggest losses) are at the top
  arrange(gain_pct)

Industry Concentration & Herfindahl Risk

Diversification reduces portfolio risk. This module quantifies concentration using sector-level exposures and calculates the Herfindahl–Hirschman Index (HHI), a standard measure of market concentration.

Now, developing a clean sequence of mathematical operators applied to grouped financial exposures.

Raw Holdings Structure:

For observations, let each portfolio holding be indexed by \(i\) and each industry by \(j \in \mathcal{J}\).

\[ (i, j, v_{ij}) \]

where:

\(i\) = security/holding index

\(j\) = minor industry

\(v_{ij}\) = base market value of holding \(i\) in industry \(j\)

Industry Aggregation:

Total exposure for industry \(j\):

\[ V_j = \sum_{i \in j} v_{ij} \]

Total Portfolio Vale:

\[ V = \sum_{j \in \mathcal{J}} V_j \]

Industry Weights:

Normalized industry weights –

\[ w_j = \frac{V_j}{V} \]

Subject to the simplex constraints:

\[ \begin{align}0 \le w_j \le 1 \\\sum_{j \in \mathcal{J}} w_j = 1\end{align} \]

Weight Vector:

\[ \mathbf{w} = (w_1, w_2, \dots, w_J) \]

Order (Ranking):

Sorted weights –

\[ w_{(1)} \ge w_{(2)} \ge \dots \ge w_{(J)} \]

Herfindahl–Hirschman Index (HHI):

Scalar definition –

\[ HHI = \sum_{j \in \mathcal{J}} w_j^2 \]

Equivalent expanded form –

\[ HHI = \sum_{j \in \mathcal{J}} \left(\frac{V_j}{V}\right)^2 \]

Vector (Euclidean norm) form –

\[ HHI = \mathbf{w}^\top \mathbf{w} = \|\mathbf{w}\|_2^2 \]

Matrix form –

Let \(\mathbf{1}\) be a vector of ones. Then:

\[ \begin{align}\mathbf{w} &= \frac{\mathbf{V}}{\mathbf{1}^\top \mathbf{V}} \\HHI &= \mathbf{V}^\top \mathbf{V} / (\mathbf{1}^\top \mathbf{V})^2\end{align} \]

Bounds:

If \(J = |\mathcal{J}|\) industries:

Perfect diversification –

\[ w_j = \frac{1}{J}, \]

\[ HHI = \frac{1}{J} \]

Complete concentration -

\[ w_k = 1, \quad w_{j \ne k} = 0, \]

\[ HHI = 1 \]

Therefore:

\[ \frac{1}{J} \le HHI \le 1 \]

Scaled HHI:

\[ HHI_{\text{scaled}} = 10{,}000 \times HHI \]

Effective Number of Industries:

Effective Number of Industries –

\[ N_{\text{eff}} = \frac{1}{HHI} \]

Complete Compact Expression:

\[ \boxed{HHI=\sum_{j \in \mathcal{J}}\left(\frac{\sum_{i \in j} v_{ij}}{\sum_{k \in \mathcal{J}} \sum_{i \in k} v_{ik}}\right)^2} \]

Other measures of interest (that will not be treated at this time):

• entropy diversification measure
• Gini concentration
• continuous limit formulation
• Beamer slides

Key outputs:

  • top industry exposures

  • concentration rankings

  • HHI statistic

Purpose:
Detect overexposure to specific industries or economic sectors.

Measure:

Using unrealised gains and total cost data, to compute security-level returns and aggregate performance across sectors and asset classes.

Key outputs:

Security-Level Definition

For each security \(i\):

\(MV_i\) : base_market_value

\(C_i\) : base_total_cost

\(G_i\) : base_unrealized_gain_loss

Identity (must hold):

\[ MV_i\,=\,G_i\,+C_i \]

Security Return:

Simple holding return –

\[ r_i\,=\,\frac{G_i}{C_i} \]

Interpretation:

  • positive \(\rightarrow\) gain

  • negative \(\rightarrow\) loss

r_i <- portfolio_df$base_unrealized_gain_loss / portfolio_df$base_total_cost

Portfolio Weights

Total portfolio market value:

\[ V = \sum_{i=1}^{N} MV_i \]

Weight of each security:

\[ w_i\,=\,\frac{MV_i}{V} \]

These weights sum to 1.

Portfolio Return

Standard portfolio return:

\[ R_p = \sum_{i=1}^{N} w_i r_i \]

This is known as the value-weighted performance.

Alternative equivalent form (and usually easier):

\[ \sum G_i = \text{Total Gain} \]

We can compute:

\[ R_p = \frac{\sum G_i}{\sum C_i} \]

Both formulas are mathematically equivalent.

Group / Sector Attribution

Grouping securities into sectors/industry \(g\).

Let:

\[ G_g = \sum_{i \in g} G_i \]

\[ C_g = \sum_{i \in g} C_i \]

define group-level aggregation sums (very common in portfolio, sector, or industry grouping).

\(i\in\,g\) = assets belonging to group \(g\)

\(G_i\) = gain/loss for asset \(i\)

\(C_i\) = cost for asset \(i\)

Sector return:

\[ R_g=\frac{G_g}{C_g} \]

Sector weight:

\[ W_g =\frac {\sum_{i \in g} MV_i}{V} \]

Contribution to portfolio:

\[ \text{Contribution}_g=W_g\,\times\,R_g \]

Key property:

\[ R_p = \sum_{g} \text{Contribution}_g \]

So contributions add up exactly.

Risk / Dispersion Measures

Performance is incomplete without volatility.

Cross-sectional variance:

\[ \sigma_p^2 = \sum_{i} w_i (r_i - R_p)^2 \]

with standard deviation:

\[ \sigma_p=\sqrt{\sigma{_p}^2} \]

Measures dispersion of gains/losses.

For holdings portfolios, returns should use market value, not cost basis. Hence:

\[ r_i=\frac{\text{unrealised gain}_i}{\text{market value}_i} \]

because:

  • weights are already market value based

  • avoids near-zero denominators

  • aligns with portfolio theory

  • industry standard

\[ \text{Base Gain or Loss}_i = \text{Base Market Value}_i - \text{Base Total Cost}_i \]

Measures how much money gained or lost (USD).

To develop a binary loss indicator when you’re modeling portfolio loss probability using base currency:

\[ \text{loss flag}_i =\begin{cases}1, \text{and if Base Unrealized Gain or Loss}_i < 0, \\0, & \text{otherwise}.\end{cases} \]

So, there’s modelling for:

Common Binary Response Setup for Logit Model (scalar form)

For observation \(i\):

\[ y\in\{0,1\} \]

Linear index:

\[ z_i = \beta_0 + \beta_1 x_{i1} + \beta_2 x_{i2} + \cdots + \beta_k x_{ik} \]

Probability form:

\[ P(y_i = 1 \mid x_i)=\frac{1}{1 + e^{-z_i}} \]

\[ P(y_i = 0 \mid x_i)=1 - \frac{1}{1 + e^{-z_i}} \]

Odds:

\[ \frac{P(y_i=1 \mid x_i)}{P(y_i=0 \mid x_i)} = e^{z_i} \]

Log-odds (logit link):

\[ \log \left( \frac{P(y_i=1 \mid x_i)}{1 - P(y_i=1 \mid x_i)} \right)=\beta_0 + \beta_1 x_{i1} + \cdots + \beta_k x_{ik} \]

The Explicit Logit Probability Model (scalar form)

\[ W = \beta_0 + \beta_1 \cdot \text{interest rate}_i + \beta_2 \cdot \text{value}_i + \beta_3 \cdot \text{cost}_i + \sum_{j=1}^{J} \gamma_j \cdot \text{industry}_{ij} + \sum_{k=1}^{K} \delta_k \cdot \text{asset\_class}_{ik} \]

\[ \Pr(\text{loss}_i = 1 \mid X_i) = \frac{1}{1 + \text{e}^{-W}} \]

\(\text{Pr}(\text{loss}_i\,=\,1\,|\,X_i)\) — probability that position \(i\) experiences a loss.

\(\beta_0\) — intercept.

\(\beta_1\,,\,\beta_2\,,\,\beta_3\) — coefficients for numeric predictors interest rate, value, cost, respectively.

\(\gamma_j\) — coefficients for the one-hot encoded industry categories \((J\,\,\text{total})\).

\(\delta_k\) — coefficients for the one-hot encoded asset_class categories \((K\,\,\text{total})\).

Use of SMOTE (Synthetic Minority Oversampling Technique) in prior

SMOTE is a method to balance class distributions in a classification dataset. Mathematically:

Let the minority class have examples:

\[ \chi_\text{minor}=\{x_1\,,x_2\,,...,\,x_N\},\,\,\,x_i\,\in\,\mathbb{R}^p \]

For eaxch minority sample \(x_i\) :

  1. Find the k nearest neighbours in feature space , \(\text{NN}_k(x_i)\)
  2. Randomly select a neighbour \(x_{\text{nn}}\)
  3. Generate a synthetic sample along the “line segment”:

\[ x_{\text{new}}=x_i\,+\,\delta\,\cdot\,(x_{\text{nn}}-x_i),\,\,\,\,\delta\,\sim\,U(0,1) \]

This generates new synthetic minority points to balance the dataset.

The original data distribution is preserved, but minority class is oversampled.

The model sees more examples of the minority class, reducing bias toward the majority class (gain in the portfolio).

Logistic Model Specification (Ridge Logit Regression - L2 Regularisation)

Logit / logistic regression predicts the probability of loss versus gain:

\[ p(y_i = 1 \mid x_i) = \frac{1}{1 + \exp(-x_i^\top \beta)} \]

Ridge adds an L2 penalty to the log-likelihood:

\[ \hat{\beta} = \arg\max_{\beta} \left\{ \ell(\beta) - \lambda \sum_{j=1}^{p} \beta_j^2 \right\} \]

where:

\[ \ell(\beta) = \sum_{i=1}^{n} \Big[ y_i \log p_i + (1 - y_i) \log (1 - p_i) \Big] \]

is the common logistic log-likelihood;

\(\lambda\,\geq\,0\) is the ridge penalty (controlled via penalty in glmnet)

Intuition:

  • Shrink coefficients toward zero → reduces overfitting

  • Handles multicollinearity in predictors (like value, cost, industry dummies)

  • Works well with many categorical dummies (one-hot encoded variables)

Feature Importance Upon a Broad Set of Features

Will now incorporate more features that are highly unique in character concerning securities in trade.

Applying now filter-based feature selection, which relies on the statistical relationship between individual features and the target variable without the overhead of a specific machine learning model.

Mathematically, FeSelectorRcpp primarily implements algorithms based on Information Theory.

  1. Entropy: The Foundation of Uncertainty

    Before determining if a feature is important, one must measure the “disorder” or uncertainty of the target variable \(Y\). Such is accomplished using Shannon Entropy:

    \[ H(Y) = -\sum_{y \in \mathcal{Y}} p(y) \log_2 p(y) \]

    where:

    \(p(y)\) is the probability of the target taking a specific value.

    The higher the entropy, the more “unpredictable” securities in the dataset are.

  2. Information Gain (IG)

    It measures how much the entropy of the target \(Y\) decreases after observing a feature \(X\).

    Mathematically, it is the difference between the original entropy and the Conditional Entropy:

    \[ IG(X)=H(Y)-H(Y|X) \]

    where \(H(Y|X)\) is the average uncertainty remaining in the target after accounting for the feature:

    \[ H(Y \mid X)=\sum_{x \in \mathcal{X}} p(x)\, H(Y \mid X = x) \]

  3. Dealing with Bias: Gain Ratio

    Standard Information Gain has a known flaw: it prefers features with many unique values (e.g., a “Securities ID” would look perfect because it’s unique, but it has no predictive power for new data).

    To rectify this, there's often use of the Gain Ratio, which normalises the Information Gain by the entropy of the feature itself (Intrinsic Info):

    \[ GR(X)=\frac{IG(X)}{H(X)} \]

    By dividing by \(H(X)\), there’s penalize on the features that have too many distinct categories, ensuring the “importance” is derived from actual patterns rather than just high cardinality.

  4. Symmetry uncertainty

    Another robust measure included is Symmetric Uncertainty (SU). This scales the Information Gain to a range of \([0,1]\), making it easier to compare features across different datasets:

    \[ SU(X,Y)=2\,\cdot\,\frac{IG(X,Y)}{H(x)+Y(y)} \]

    • 0: Feature and target are completely independent.

    • 1: The feature perfectly predicts the target.

Feature Importance development.

FSelectorRcpp is specifically designed to handle factors (categorical data) natively because its underlying mathematical framework is based on Information Theory.

Unlike many machine learning algorithms that require you to manually “One-Hot Encode” or “Dummy Code” your variables, FSelectorRcpp prefers factors.

The package treats each level of a factor as a distinct state in the probability distribution. When calculating Entropy \(H(X)\), it simply counts the frequency of each factor level to determine \(p(x)\).

If you provide numeric features, FSelectorRcpp will typically discretize them internally (often using the MDL - Minimum Description Length method) to turn them into categorical-like bins. This is because Shannon Entropy is natively defined for discrete distributions.

  • Factors: Processed directly as discrete sets.

  • Numerics: Automatically binned so that Information Gain can be calculated.

However, will encode factor attributes, because in the future will likely apply machine learning models that operate on quantitative values.

Random Forest

A Random Forest is an ensemble of decision trees. It improves prediction accuracy by averaging the results of many individual trees, which reduces the risk of overfitting.

The structure relies on two main mathematical techniques:

  • Bagging (Bootstrap Aggregation): Each tree is trained on a random sample of the data, drawn with replacement.

  • Feature Randomness: At each split in a tree, only a random subset of features is considered.

Individual Tree Prediction

For a single decision tree \(h_k(x)\), the prediction for an input \(x\) is based on the terminal node (leaf) the data point falls into.

Forest Aggregation (Regression)

For regression tasks, the Forest prediction \(H(x)\) is the numerical average of all \(K\) trees:

\[ H(x) = \frac{1}{K} \sum_{k=1}^{K} h_k(x) \]

For classification, the forest uses Majority Voting. The predicted class \(\hat{Y}\) is the one that receives the most “votes” from the individual trees:

\[ \hat{Y} = \text{arg max}_{y} \sum_{k=1}^{K} I(h_k(x) = y) \]

Where \(I(\cdot)\) is the indicator function, which equals 1 if the tree predicts class \(y\) and 0 otherwise.

Decision trees within the forest usually split nodes by minimizing Gini Impurity (\(G\)). For a set of items with \(J\) classes, the probability of an item being classified into class \(i\) is \(p_i\):

\[ G = 1 - \sum_{i=1}^{J} p_i^2 \]

Outlier Sabotage

Notice the correlation of -0.04. In a linear calculation (Pearson), those massive outliers on the right side of the “NoLoss” row (the points at \(2 \times 10^5\)) and the “Loss” row (the point at \(5 \times 10^4\)) pull the math toward zero.

  • The Problem: Correlation is extremely sensitive to outliers. A few massive gains that aren’t flagged as losses are “distracting” the linear calculation.

  • The RF Strength: Random Forest doesn’t care about the distance (the value); it only cares about the rank. It sees that almost all “Loss” flags occur when the value is below zero, regardless of whether it’s \(-1\) or \(-100,000\).

The Random Forest is essentially acting as a “Noise Filter.” It has learned to ignore those massive outliers and focus on the fact that \(0\) is the “cliff” where a security becomes a loss.
