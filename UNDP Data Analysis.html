Synopsis

This project applies the United Nations Development Programme (UNDP) Data Futures platform (United Nations Development Programme, n.d.) to develop conventional data analysis and models. By aggregation of high-frequency indicators across human development, planetary pressure, and socioeconomic vulnerability, the platform provides a multidimensional view of global progress or retrogression. This study demonstrates how the assimilation of UNDP’s open-source data allows for the application of data modeling, predictive analytics and general machine learning techniques.

Introduction

The UNDP Data Futures Platform is designed to translate complex global challenges into actionable insights. Its primary purpose is to provide a “single source of truth” for the Sustainable Development Goals (SDGs) and beyond, offering a data oriented repository for policymakers, researchers, and data scientists.

Unlike conventional static databases, the platform is intended for dynamic exploration. It permits users to observe or develop models for the “trade-offs” between unique development perspective—for example, how economic growth might correlate with carbon emissions or how gender equality can be tied to national GDP. Its intended use is to empower stakeholders to extend beyond isolated repositories of information controlled by specific departments, teams, or systems within an organisation, inaccessible to others. Hence, the ability to observe dynamic development through an integrated, systemic lens.

Such UNDP ecosystem enables Longitudinal and Comparative Analysis:

  • Trend Analysis: For example, identifying the “velocity” of development—not just where a country is, but how fast it is improving or declining in specific sectors.

  • Correlation Studies: Exploring the intersectionality of crises, such as how debt levels in developing nations influence their capacity for climate change adaptation.

The UNDP’s high-granularity data is particularly valuable for training advanced Machine Learning (ML) models:

  • Predictive Analytics: Developing regression models and non-parametric models (ensemble types) or Time-Series Forecasters (e.g., ARIMA or LSTMs) to predict future development trajectories.

  • Clustering & Pattern Recognition: Applying Unsupervised Learning (e.g., K-Means or Hierarchical Clustering) to group nations based on shared factors, vulnerabilities, dynamic, etc. rather than on geography or the tendency to pursue a geopolitical branding. This reveals “hidden” peers—countries that share similar developmental hurdles despite being on different continents. As well, can also reveal concealed uniqueness or disparities among countries that may generally not be recognised.

Data Dictionary

Instead of the conventional construction of tables for the definition of attributes, to take advantage of the name of each data file acquired from the UNDP Data Futures platform. The name of each data file explicitly identifies the indicator or attribute to apply. Furthermore, there’s over 20 data files considered in this project. Hence, will simply automate the process of identifying each indicator or attribute.

library(readr)
library(purrr)

folder_path <- "C:/Users/verlene/Downloads"

# Get file info
files_info <- list.files(
  path = folder_path,
  pattern = "\\.csv$",
  full.names = TRUE
) |> 
  file.info()

# Filter for files modified on 2026-03-22
target_date <- as.Date("2026-03-22")

filtered_files <- rownames(files_info)[
  as.Date(files_info$mtime) == target_date
]

# Read filtered files
data_list <- map(filtered_files, read_csv)

# Name them
names(data_list) <- basename(filtered_files)

# Print with spacing

  cat("Dataset:", names(data_list)[i], "\n")

Now, one of the most annoying aspects of panel data, is the high quantity of missing values often present. Elastic Net

The Elastic Net is a regularised regression method designed to overcome the specific limitations of Lasso and Ridge regression (Zou & Hastie, 2005). It is particularly powerful when dealing with datasets where predictors are highly correlated (multicollinearity) or when the number of predictors (\(p\)) exceeds the number of observations (\(n\)).

To understand the purpose of Elastic Net, you have to look at the two methods it combines:

  1. The Lasso Problem (\(L_1\)): Lasso is great for feature selection because it shrinks coefficients to exactly zero. However, if you have a group of highly correlated variables (e.g., “Years of Schooling” and “Literacy Rate”), Lasso will arbitrarily pick one and discard the others. This makes the model unstable.

  2. The Ridge Problem (\(L_2\)): Ridge is excellent at handling correlated variables by shrinking coefficients toward each other, but it never sets them to zero. This leaves you with a “dense” model that is hard to interpret because every variable is still included.

Elastic Net acts as a compromise, using a convex combination of both penalties to achieve a “grouping effect” where correlated predictors are retained or dropped together.

The Elastic Net is a regularised regression method that combines the penalties of Lasso (\(L_1\)) and Ridge (\(L_2\)) regression.

It minimizes the following objective function:

\(\min_{\beta} \left\{ \frac{1}{2n} \sum_{i=1}^{n} (y_i - x_i^T\beta)^2 + \lambda \left[ \frac{1-\alpha}{2} \sum_{j=1}^{p} \beta_j^2 + \alpha \sum_{j=1}^{p} |\beta_j| \right] \right\}\)

The Three Components:

  • Loss Function: \(\frac{1}{2n} \sum (y_i - x_i^T\beta)^2\) — The standard Mean Squared Error (MSE) from OLS.

  • \(L_2\) Penalty (Ridge): \(\sum \beta_j^2\) — Shrinks coefficients toward zero, handling multicollinearity by grouping correlated variables.

  • \(L_1\) Penalty (Lasso): \(\sum |\beta_j|\) — Forces some coefficients to exactly zero, performing automatic feature selection.

The Tuning Parameters:

  • \(\lambda\) (Lambda): Controls the overall strength of the penalty. A higher \(\lambda\) leads to more shrinkage.

  • \(\alpha\) (Alpha): Controls the mix between Ridge and Lasso.

    • \(\alpha = 0\): Pure Ridge Regression.

    • \(\alpha = 1\): Pure Lasso Regression.

    • \(0 < \alpha < 1\): Elastic Net (the “compromise”).

Random Forest Feature Importance

Random Forest measures feature importance primarily through Mean Decrease in Impurity (Gini Importance) or Permutation Importance (Breiman, 2001).

Feature importance is based on how much a feature reduces impurity across all trees.

In tree-based ensembles like Random Forest, feature importance is calculated by measuring how much each feature contributes to reducing the “clutter” or “error” (impurity) in the model.


Total Feature Importance

The overall importance of a feature \(j\) is the average of the impurity decreases it causes across all trees in the forest.

\[ FI_j = \frac{1}{T}\sum_{t=1}^{T}\sum_{n\in N_{j,t}} \Delta I(n) \]

Where:

  • \(FI_j\): Importance of feature \(j\).

  • \(T\): Total number of trees in the ensemble.

  • \(N_{j,t}\): The set of all nodes in tree \(t\) where feature \(j\) was used to perform a split.

  • \(\Delta I(n)\): The impurity decrease achieved at node \(n\).

Impurity Decrease at a Specific Node

To find the decrease at a single node, we subtract the weighted impurity of the two child nodes from the impurity of the parent node.

\[ \Delta I(n) = I(n) - \left(\frac{N_L}{N} I(n_L) + \frac{N_R}{N} I(n_R) \right) \]

Where:

  • \(I(n)\): Impurity at node \(n\) (Gini Impurity for classification or MSE for regression).

  • \(n_L, n_R\): The left and right child nodes resulting from the split.

  • \(N\): Total samples at the parent node \(n\).

  • \(N_L, N_R\): Number of samples that moved to the left and right children, respectively.

A feature is considered “important” if it is frequently chosen for splits that significantly clean up the data (reducing Gini or MSE) across the entire forest.

Gradient Boosting: The Concept of “Learning from Mistakes”

Gradient Boosting is an ensemble machine learning technique that builds a model in a sequential manner. Instead of training many models in parallel (like Random Forest), it trains one model at a time, where each new model attempts to correct the errors made by the previous ones (Friedman, 2001).

  • The Process: It starts with a simple “weak” model (usually a small decision tree). It calculates the residuals (the difference between the actual value and the prediction). The next tree is then trained specifically to predict those residuals.

  • The “Gradient” Part: It uses a gradient descent algorithm to minimize a “Loss Function” (the measure of how wrong the predictions are) as it adds each new tree.

To understand the mathematical structure of these algorithms, it helps to view them as a process of additive functional optimisation.

Functional Gradient Descent. In standard Gradient Boosting, we aim to find a function \(\hat{f}(x)\) that minimizes a loss function \(L(y, f(x))\). Instead of updating parameters (like weights in a neural network), we add new functions (weak learners) sequentially.

  • Initial Model: Start with a constant value, usually the mean of the target: \(f_0(x) = \text{argmin}_\gamma \sum L(y_i, \gamma)\).

  • Iterative Step: For each step \(t\), we calculate the pseudo-residuals, which are the negative gradients of the loss function with respect to the current predictions:

\[ r_{it} = -\left[\frac{\partial L(y_i, f(x_i))}{\partial f(x_i)} \right]_{f(x)=f_{t-1}(x)} \]

  • Update: We train a new weak learner \(h_t(x)\) (a tree) to predict these residuals and update the model:

\[ f_t(x) = f_{t-1}(x) + \nu \cdot h_t(x) \]

where \(\nu\) is the leearning rate of “shrinkage”

XGBoost: The Taylor Expansion Approach. XGBoost improves on this by using a Second-Order Taylor Expansion to approximate the loss function. This allows it to account for the curvature (Hessian) of the loss, leading to faster convergence (Friedman, 2001; Hastie, Tibshirani and Friedman, 2009; Chen and Guestrin, 2016) .

The objective function at iteration \(t\) is:

\[ \text{Obj}^{(t)} = \sum_{i=1}^n [L(y_i, \hat{y}_i^{(t-1)}) + g_i f_t(x_i) + \frac{1}{2} h_i f_t^2(x_i)] + \Omega(f_t) \]

where:

  • \(g_i\) (Gradient): First-order derivative of the loss.

  • \(h_i\) (Hessian): Second-order derivative of the loss.

  • \(\Omega(f_t)\) (Regularization): Penalizes model complexity to prevent overfitting: \(\Omega(f) = \gamma T + \frac{1}{2}\lambda \sum w_j^2\) (where \(T\) is the number of leaves and \(w\) are leaf weights).

XGBoost Feature Importance. Mathematically, feature importance is derived from how much each variable contributes to reducing the objective function during the tree construction.

  • Gain: This is the most mathematically rigorous metric. For a specific split, the “Gain” is calculated as:

\[ \text{Gain} = \frac{1}{2} \left[ \frac{G_L^2}{H_L + \lambda} + \frac{G_R^2}{H_R + \lambda} - \frac{(G_L + G_R)^2}{H_L + H_R + \lambda} \right] - \gamma \]

where:

  • \(G\) and \(H\) represent the sum of gradients and Hessians in the Left and Right child nodes.

  • A high Gain means the split significantly improved the model’s ability to fit the data relative to the complexity penalty (\(\gamma\)).

Final Validation: Calculating RMSE. To observe which model “won” in terms of raw accuracy, we calculate the Root Mean Squared Error.

NOTE: will focus on on Random Forest and XGBoost because Elastic net is confined to a linear model assumption will the two ensemble models are overall non-parametric.

\[ \mathrm{RMSE} = \sqrt{\frac{1}{n} \sum_{i=1}^{n} (y_i - \hat{y}_i)^2} \]

It is:

  • The square root of the average squared prediction errors

  • Sensitive to large errors (because of squaring)

Scale Matters:

RMSE is expressed in the same units as the target variable

  • Example: if predicting house prices → RMSE is in dollars

  • If predicting temperature → RMSE is in degrees

This makes RMSE directly interpretable in real-world terms.

Lower is Better:

  • RMSE = 0 → perfect predictions
  • Smaller RMSE → better model fit
  • Larger RMSE → larger average prediction error

Compare Relative to Data Scale:

RMSE is meaningful only in context:

  • Compare RMSE to:
-    Mean of the target

-    Standard deviation of the target

-    Range of the target

Rule of thumb:

  • RMSE ≪ standard deviation → good model

  • RMSE ≈ standard deviation → weak model

  • RMSE > standard deviation → poor performance

Structural Discovery or Segmentation with Clustering

Clustering is a solid next step for structural discovery / segmentation in the UNDP-style dataset. The goal is to uncover natural groupings of countries based on socio-economic indicators, without using HDI solely for interpretation.

K-Means Clustering

K-means clustering is an unsupervised machine learning algorithm that partitions unlabeled datasets into distinct, non-overlapping clusters based on feature similarity. It iteratively minimizes the sum of squared distances between data points and their cluster centroid, assigning points to the nearest center and updating centroids until convergence (MacQueen, 1967; Hartigan and Wong, 1979).

The mathematical goal of K-means clustering is to partition \(n\) observations into \(K\) clusters by minimizing the Within-Cluster Sum of Squares (WCSS).

The Objective Function:

The algorithm seeks to find \(K\) clusters (\(S = \{S_1, S_2, \dots, S_K\}\)) that minimize the squared Euclidean distances between points and their assigned cluster centers (centroids \(\mu_i\)):

\[ J = \sum_{i=1}^{K} \sum_{x \in S_i}|x-\mu_i \|^2 \]

The iterative Process:

K-means reaches this minimum through two alternating steps:

  1. Assignment Expectation –

Each observation \(x_j\) is assigned to the cluster with the nearest centroid.

\[ S_i^{(t)} = \{x_j: \|x_j - \mu_i^{(t)} \|^2 \le \|x_j -\mu_{i^*}^{(t)} \|^2, \forall i^* \} \]

  1. Update (Maximisation) –

The centroids are recalculated by taking the mean of all points assigned to that cluster.

\[\mu_i^{(t+1)} = \frac{1}{|S_i^{(t)}|} \sum_{x_j \in S_i^{(t)}} x_j\]

Key Concepts for the UNDP Data:

  • Centroid (\(\mu\)): The “average” country profile for that cluster (e.g., a “Mid-HDI” cluster centroid).

  • Euclidean Distance: The straight-line distance in multi-dimensional space (e.g., distance between a country’s schooling/urbanization and the cluster average).

  • Convergence: The process stops when assignments no longer change, meaning the WCSS has reached a local minimum.
